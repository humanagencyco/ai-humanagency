Harness · Explained

What is a harness?

The harness is everything around an AI model that turns it from a chatbot into something that can do a job. The model is the brain. The harness is the rest of the body: eyes, hands, a rulebook, and a way to check its own work.

In one line: Agent = Model + Harness. The model is the engine. The harness is the car around it: steering, brakes, dashboard and road rules.

A model on its own can only talk

Ask a model on its own, "Check whether my order has shipped", and it can only guess, because it cannot look at your orders. Give it a harness with a tool that can read your order system, a rule that says "only report what the system says", and a check that the answer quotes a real order number, and it can actually do the job.

It's the same for code. A model alone can only write text about a bug. Inside a harness it can read the files, run the tests, see the failures, edit the code and stop when the tests pass. Same model, different system, very different result.

How we got here

  1. 1Prompt engineering (2022 to 2024)What you say to the model. "How should I ask?"
  2. 2Context engineering (2025)What the model sees. "What information should it have?"
  3. 3Harness engineering (2026 onwards)The whole system it runs in. "How does it do the job reliably?"

Each layer contains the one before: the prompt sits inside the context, and the context is one part of the harness.

The five parts

There's no official list, but most working harnesses have these five. Each answers a question the model can't answer for itself.

  1. 1Context: what it knowsInstructions, documents it can search, notes from earlier steps, and summaries that stop long tasks overflowing.
  2. 2Action: what it can touchTools such as looking up an order, sending an email, browsing or running code. Clear tool descriptions matter as much as the tools.
  3. 3Orchestration: how it plansThe steps, their order, keeping track of progress, handing parts to sub-agents, and what happens when a step fails.
  4. 4Control: what it's allowed to doPermissions, a person approving anything risky such as a refund, a safe sandbox, and limits on time and spend.
  5. 5Feedback: how you know it worksLogs of what it did, checks it runs on its own work, and evals to measure quality over time. Every mistake becomes a new rule, tool or check.

A quick test for any AI system

Does it know enough? Can it act? Does it stay on track? Is it safe? Can we show that it works, and that it's getting better?

If you can't answer one of these, that's the part of the harness to look at first.

Why it matters

Most AI problems that people blame on the model are harness problems. The model invented a refund policy because nothing told it to look the policy up. It looped for an hour because nothing set a limit. It worked in a demo because nothing checked it on real cases.

When something goes wrong, ask: is it the model, or the harness around it? The fix is often in the harness.
